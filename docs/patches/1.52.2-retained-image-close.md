# Close retained subscription images exactly once

Reviewed 2026-09-13 against upstream Aeron `1.52.2`, commit
`5b62f21d917af027cdf5a3241aa5f355149b04fa`. This PR is independent of the
destination-registration and spy-removal PRs.

## Bug and example

`aeron_subscription_image_by_session_id` acquires an external image reference.
For one retained image the reference count is two: subscription + application.
In `aeron_client_conductor_linger_or_delete_all_images`, upstream's current-image
loop drops the subscription reference (2 → 1), then adds the image to lingering
resources. The second loop sees the same subscription and the initial
`removal_change_number == INT64_MAX`, and drops that reference again (1 → 0).
Later conductor maintenance deletes the image while the application still owns
its handle. Reading its position/closed state can then use freed memory.
The retained branch also never calls `aeron_image_close`.

Concrete sequence: create an IPC publication/subscription, retain its image,
close the subscription, drive conductor maintenance, read the retained image.
This was reached by a Rust Archive recording session during snapshot replay;
the defect is in the native client's reference accounting, not Rust replay logic.

## Correction and adversarial findings

In [the conductor](../../aeron-client/src/main/c/aeron_client_conductor.c), close
each current image, deliver its unavailable callback while the subscription and
its reference are still valid, then drop that reference once. Clear the detached
subscription pointer and set `removal_change_number = INT64_MIN` before adding
the image to lingering resources. Delete only if no references remain.

Review of the earlier `a0963b7f67` patch found two callback issues, corrected here:

- It cleared `image->subscription` before invoking the zero-retain callback,
  so `aeron_image_constants().subscription` unexpectedly became null during it.
- Its callback still ran only for zero-retain images. Owners releasing their
  retained images in that callback never received it.

Calling the callback before the reference decrement also permits it to release
owned references or acquire a new reference without using a stale pre-callback
count. Image destruction remains conductor-owned; `aeron_image_release` only
decrements atomically. Already-unavailable images are not notified twice.

[Java ClientConductor.closeImages](../../aeron-client/src/main/java/io/aeron/ClientConductor.java)
closes all images and notifies their unavailable handlers. This fix restores
those lifecycle effects, not byte-for-byte Java implementation or Java GC lifetime.
No allocations, locks, or instructions are added to message polling/offering.

## Regression and evidence

[RetainedImageCloseTest](../../aeron-client/src/test/c/aeron_client_conductor_test.cpp)
drives actual client conductor code via encoded driver notifications and a real
mapped log. Its 24 parameter combinations cover invoker/queued close, 0/1/2
retains, release in the unavailable callback/after close, and current/already
unavailable images. Assertions cover one callback, closed state, nonzero final
position 64, valid callback subscription constants, exact remaining reference
count, and eventual zero lingering resources.

Fresh macOS arm64 / AppleClang 21 ASan+UBSan results, 2026-09-13:

| Source | Check | Result |
|---|---|---|
| Upstream 1.52.2 | one-retain queued-close case | FAIL: expected refcount 1, actual 0; callback absent |
| Previous patch2 | initial 12-case current-image matrix | 12 failed: null callback constants or missing callback |
| Corrected combined source | final 24-case lifetime matrix | 24 passed |
| Corrected combined source | six affected native suites | 235 passed; no sanitizer diagnostics |
| This patch alone on upstream | entire client-conductor suite | 102 passed, including 24 lifetime cases |
| Combined source, Rust wrapper + embedded native driver | retained-image live regression | 1 passed, 0 failed/ignored |

The independent test source was exported from this PR's exact staged source
tree, not the combined working checkout. Retained log
`lifetime-independent-tests.log` SHA256:
`55daaf5af9bbae72cd4408d3f6a57948575d2e3b0af01187e2e55f60be6382bb`.
Logs for this review were written to `/tmp/aeron-native-review-20260913/`;
this compact result record is retained in Git even if temporary logs are cleaned.

These are native unit tests, not a claim of threaded stress, full snapshot
recovery or Docker acceptance. Queued mode is driven on one test thread.
New-reference acquisition inside the callback and every concurrent interleaving
are source-reviewed but not separately tested. The API still requires applications
not to use images after the Aeron client itself is destroyed; this patch only
extends the correct subscription-close lifetime. Allocation-failure handling in
the pre-existing linger path is unchanged.

## Reproduce

```sh
cmake -S . -B build-native-review -DAERON_TESTS=ON -DAERON_UNIT_TESTS=ON \
  -DAERON_SYSTEM_TESTS=OFF -DAERON_BUILD_SAMPLES=OFF \
  -DAERON_BUILD_DOCUMENTATION=OFF -DSANITISE_BUILD=ON -DCMAKE_BUILD_TYPE=Debug
cmake --build build-native-review --target client_conductor_test --parallel 1
build-native-review/binaries/client_conductor_test --gtest_filter='CloseModes/*'
```

Run the same added tests against the upstream conductor to reproduce the
reference-count failure. Do not copy the fix along with the tests for this
negative control. JDK 17+ is required by upstream CMake configuration; no JVM
runs in these tests. The commands are suitable for macOS/Linux; this review's
fresh native measurements were on macOS, not Linux.
