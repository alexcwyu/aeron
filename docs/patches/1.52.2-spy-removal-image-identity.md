# Preserve image identity when removing a spy destination

Reviewed 2026-09-13 against Aeron `1.52.2` (`5b62f21d91`). Independent PR;
neither client patch is required for this driver correction.

## Failure and path

1. A manual subscription adds a spy destination for a network publication.
2. The available-image notification identifies the publication, for example ID 2.
3. Removing the destination correctly removes the driver-side subscription link
   and acknowledges the operation.
4. Its unavailable-image notification incorrectly uses ID 0.
5. The client looks up the image by `(image ID, subscription ID)`. The wrong ID
   finds nothing, leaving the removed image in the client's subscription list.

An acknowledgement therefore does not prove image removal. A subsequent
same-session admission can see two images, rather than the expected one, and
fail closed. Masking the image count in Rust would hide stale native state.

## Root-cause correction

[aeron_network_publication_create](../../aeron-driver/src/main/c/aeron_network_publication.c)
did not initialize `conductor_fields.subscribable.correlation_id`. Set it to
`registration_id`, matching the publication's available-image identity.

[aeron_driver_conductor_on_remove_receive_spy_destination](../../aeron-driver/src/main/c/aeron_driver_conductor.c)
calls `subscription_link_notify_unavailable_images`, which consumes this field.
IPC publications and publication images already initialize their analogous
field. [Java DriverConductor.cleanupSpies](../../aeron-driver/src/main/java/io/aeron/driver/DriverConductor.java)
also uses the publication registration ID for unavailable notifications.

One initialization in the common constructor fixes all such notification
callers. No message copying, payload layout, flow control, allocation, lock,
publication ordering or hot-path poll/offer changes are introduced.

## Regression and verified evidence

[shouldNotifyCorrectImageWhenRemovingSpyDestination](../../aeron-driver/src/test/c/aeron_driver_conductor_spy_test.cpp)
uses the existing native driver fixture and real conductor commands. It creates
a network publication and a manual subscription, adds the spy, captures its
available-image ID, removes it, and verifies one unavailable notification with
the same ID/subscription/stream/channel, the right operation acknowledgement,
and removal of the spy subscription. The expected ID comes from the available
notification, independently checked against the publication ID, not from the
new field being tested.

Fresh AppleClang 21/macOS arm64 ASan+UBSan, 2026-09-13:

| Source | Result |
|---|---|
| Upstream 1.52.2 plus regression | FAIL: unavailable image ID 0, expected 2 |
| Corrected combined source | regression passed; spy suite 18/18; six suites 235/235 |
| This patch alone on upstream | entire native spy suite 18/18, no sanitizer diagnostics |

The independent suite was built from this PR's exact exported staged source.
Its `spy-independent-tests.log` SHA256 is
`583e4c46c20a20abb0f5335bcfb4757d884108d0a0ec515f0441cc376b823dce`.
Review logs were written to `/tmp/aeron-native-review-20260913/`; these summarized
results remain in Git after temporary-log cleanup.

An initial negative-control fixture held a pointer to a temporary channel
string in a deferred matcher. ASan caught a test-only UAF during failure
reporting; the matcher now owns the string. The repeated upstream negative
control exits 1 for the wrong image ID without that fixture error.

Earlier downstream evidence on the one-line spy correction: the Rust Archive3
two-image admission/removal regression passed, as did four real Docker recovery
cells (W1/W32 × T3/T4, 20K RTTs, dual-archive auditing). Those runs preceded the
new retained-image callback correction; they are corroboration for this spy
fix, **not** fresh combined-source Docker acceptance. This native unit test
observes the driver notification; it does not itself run a client image list or
a Rust archive server.

## Reproduce

```sh
cmake -S . -B build-native-review -DAERON_TESTS=ON -DAERON_UNIT_TESTS=ON \
  -DAERON_SYSTEM_TESTS=OFF -DAERON_BUILD_SAMPLES=OFF \
  -DAERON_BUILD_DOCUMENTATION=OFF -DSANITISE_BUILD=ON -DCMAKE_BUILD_TYPE=Debug
cmake --build build-native-review --target driver_conductor_spy_test --parallel 1
build-native-review/binaries/driver_conductor_spy_test \
  --gtest_filter='*shouldNotifyCorrectImageWhenRemovingSpyDestination'
```

Delete only the new correlation-ID initialization and repeat to reproduce the
failure. Configuration requires JDK 17+; the test uses no runtime JVM. Commands
work on macOS/Linux; fresh native execution here was macOS only.
