# Address destination commands to the original publication

Reviewed 2026-09-13 against Aeron `1.52.2` (`5b62f21d91`). Independent PR;
no dependency on the image-lifetime or spy-removal patches.

## Bug and correction

Two clients registering the same non-exclusive network publication receive
different client registration IDs, but share one original publication ID.
Example: underlying publication 777, second client's handle 1. Add/remove
destination commands must target 777, not 1: the driver searches its network
publications by underlying publication identity.

[aeron_client_conductor_get_async_registration_id](../../aeron-client/src/main/c/aeron_client_conductor.c)
incorrectly chose `registration_id` for publication resources. Choose
`original_registration_id` for publication and exclusive-publication resources.
Subscription resources keep their subscription registration ID. Ordinary
exclusive publications do not share and have equal IDs, so that branch is
normally behavior-neutral.

The helper is used by URI destination commands and destination-ID commands.
This does **not** change the identity returned by async publication registration,
the command's own correlation ID, completion matching, timeout, or publication
close ownership. Closing a client handle still removes its client registration.

[Java Publication](../../aeron-client/src/main/java/io/aeron/Publication.java)
uses `originalRegistrationId` in synchronous add/remove-destination methods.
Its 1.52.2 async counterparts use `registrationId`; therefore blanket Java API
parity would be an incorrect claim. The decisive contract here is the native
[driver destination lookup](../../aeron-driver/src/main/c/aeron_driver_conductor.c).

## Regression, anti-cheat and results

[shouldTargetOriginalPublicationForDestinationCommands](../../aeron-client/src/test/c/aeron_client_conductor_test.cpp)
delivers a publication-ready response with unequal IDs, then inspects the actual
outbound ring-buffer command for both URI add and remove. It asserts original
target ID 777, unchanged operation correlation, exact URI, and one command per
operation; then checks completion polling. Merely injecting an operation-success
response cannot satisfy the wire-field assertions.

This is a native client unit test: the driver-ready and success responses are
simulated protocol inputs, not a live shared-publication integration claim.

Fresh AppleClang 21/macOS arm64 ASan+UBSan, 2026-09-13:

| Source | Result |
|---|---|
| Upstream 1.52.2 plus regression | FAIL: both commands target 1, expected 777 |
| Corrected combined source | regression passed; six affected suites 235 passed |
| This patch alone on upstream | entire client-conductor suite 79 passed |
| Combined source, live Rust wrappers/native driver | four multi-destination tests passed, including two-client shared publication |

The independent suite was built from this PR's exact exported staged source.
Its `registration-independent-tests.log` SHA256 is
`809e65146ac36ee34386f95aae67bc21b7a16cf374da65505f490dbe1f37d090`.
Review logs were written to `/tmp/aeron-native-review-20260913/`; these summarized
results remain in Git after temporary-log cleanup. The live shared-publication
test covers add-destination completion; the native test additionally checks URI
removal's actual wire target. Neither proves remove-by-ID correctness.

No hot-path allocation, lock, protocol layout or ABI change. The correction is
two field selections on the control path.

## Separate pre-existing finding, not fixed by this PR

`aeron_client_conductor_on_cmd_destination_by_id` assigns
`destination_registration_id = resource_registration_id`, rather than the
destination ID supplied by the caller. This is already present in upstream
1.52.2. Correcting the publication target does not repair this second bug.
Remove-by-ID is consequently **not** claimed fixed/tested by this PR; it needs a
separate regression and correction. Do not silently fold that distinct defect
into this two-line registration patch.

## Reproduce

```sh
cmake -S . -B build-native-review -DAERON_TESTS=ON -DAERON_UNIT_TESTS=ON \
  -DAERON_SYSTEM_TESTS=OFF -DAERON_BUILD_SAMPLES=OFF \
  -DAERON_BUILD_DOCUMENTATION=OFF -DSANITISE_BUILD=ON -DCMAKE_BUILD_TYPE=Debug
cmake --build build-native-review --target client_conductor_test --parallel 1
build-native-review/binaries/client_conductor_test \
  --gtest_filter='*shouldTargetOriginalPublicationForDestinationCommands'
```

For the negative control keep the test and restore only the two production
field selections to `registration_id`. No external driver or JVM is used by
this test. Upstream CMake requires JDK 17+ at configuration time. Linux commands
are the same; this review does not claim a fresh Linux run.
